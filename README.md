# 经营分析示例：订单 / 退款 / 投放（三种粒度的正确汇总）

一个零依赖的本地示例（Python 标准库 + SQLite + 原生前端），演示经营分析页面
如何在**粒度不同**的三张表上正确计算指标，并能逐指标下钻查看参与计算的
明细与实际执行的 SQL。

## 运行

```bash
python3 app/server.py        # 默认 8000 端口，PORT 环境变量可改
# 打开 http://localhost:8000
```

运行测试：

```bash
python3 tests/test_core.py
```

## 三张表，三种粒度

| 表 | 粒度 | 可用维度 |
|---|---|---|
| `order_lines` 订单商品明细 | 一行 = 一个商品行（一单多条） | 日期、门店、渠道 |
| `refunds` 退款明细 | 一行 = 一笔退款（一单可多次退款） | 退款日期、门店、渠道 |
| `ad_spend_daily` 每日投放 | 一行 = 一天一个渠道 | 日期、渠道（**无门店**） |

样本数据内置了所有需要演示的场景：

- **一单多次退款**：O1001 当天退 10.00、次日又退 25.00；
- **一单多条明细**：O1001（奶茶+珍珠）、O1004（蛋糕+饼干，空白渠道）；
- **空白渠道**：O1004 的渠道为空字符串，页面归入「（空白）」；
- **只有退款没有订单的日期**：2026-11-12（R9003 全额退款）；
- **缺少记录 vs 实际为零**：2026-11-11 饿了么有 0 元投放记录（实际为零），
  2026-11-12 饿了么没有任何记录（显示 —）；O1006 是 0 元赠品行。

## 口径规则（正确模式）

1. **先各自汇总，再对齐**：每个指标先按自己可用的维度聚合，键集取 UNION
   后逐个 LEFT JOIN 到查询粒度。绝不把三张表直接关联——订单行 × 退款笔数
   × 投放行会互相扇出，金额被重复计算。
2. **不用 `SUM(DISTINCT …)` 掩盖重复**：样本里两笔奶茶都是 30.00 元，
   DISTINCT 会把合法记录合并丢掉。
3. **投放没有门店维度**：按门店分组时投放列显示「不可拆分」，绝不把整天
   花费复制到每家门店；筛选门店时投放卡片/合计保持全量并给出提示。
4. **只有退款没有订单的日期保留**（键集 UNION 而非 INNER JOIN）。
5. **缺少记录（—）与实际为零（0.00）分别展示**。

可配置的口径（修改后页面自动重新预览计算过程）：

- 退款归属：按退款发生日 / 按原订单日期；
- 空白渠道：归入「（空白）」/ 剔除空白渠道记录。

## 错误示例对照

页面右上角切换到「错误示例（直接关联）」：

```sql
FROM order_lines ol
LEFT JOIN refunds rf       ON rf.order_id = ol.order_id
LEFT JOIN ad_spend_daily sp ON sp.spend_date = ol.order_date
                          AND sp.channel   = ol.channel
```

对照表逐格展示 正确 / 错误 / 差异，并列出：

- **被重复计算的原始记录**：如 O1001 的两条明细各被计 2 次、
  2026-11-10 美团的 200 元投放被计 5 次（多计 800）；
- **被丢弃的记录**：2026-11-12 的投放没有订单承接，整列丢失；
- **整行丢失的分组**：只有退款没有订单的 2026-11-12。

## 下钻与导出

- 点击指标卡片 → 该指标在当前筛选下的全部参与明细 + 实际执行的 SQL；
- 点击表格中的金额单元格 → 该分组桶的参与明细 + SQL；
- 「导出结果」下载 zip：`经营分析结果.csv`（当前表格，UTF-8 带 BOM）
  + `口径与筛选条件.json`（模式、口径配置、筛选条件、分组、合计、
  本次实际执行的 SQL）。

## API

| 路径 | 说明 |
|---|---|
| `/api/meta` | 门店/渠道/日期范围/口径说明 |
| `/api/summary` | 正确口径汇总（卡片 + 表格行 + 趋势 + SQL 步骤） |
| `/api/compare` | 正确 vs 错误对照（含重复记录、丢弃记录、丢失键） |
| `/api/detail` | 单指标下钻明细（`metric` + `b_date/b_store/b_channel`） |
| `/api/export` | 导出 zip（结果 CSV + 口径与筛选 JSON） |

公共参数：`mode`、`date_from`、`date_to`、`store`、`channel`、
`group_by`、`refund_date_basis`、`blank_channel`。

## 目录

```
app/
  db.py        # 建表 + 样本数据（金额以“分”存储，避免浮点误差）
  queries.py   # 正确/错误两条 SQL 路线、下钻、重复计数分析
  server.py    # 纯标准库 HTTP 服务 + 导出
  static/      # 原生 HTML/JS/CSS，SVG 分组柱状图（无第三方依赖）
tests/
  test_core.py # 14 项口径测试（正确数字、错误对照、导出）
```
